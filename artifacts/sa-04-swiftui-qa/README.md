# SA-04 SwiftUI QA

## Проверено

- Xcode `.app` запускалась в отдельной копии с отдельным bundle ID, а выбранная папка содержала только синтетические файлы в `/tmp`.
- В библиотеке проверены пустое состояние и строка источника со статистикой `2 documents · 3 passages` и итогом `Index up to date`.
- Через тестовый JSON Lines bridge проверены поисковые карточки с разными страницами PDF и раздел «Sources Used» с двумя источниками, соответствующими hits, переданным команде `answer`.
- Python индексатор и bridge дополнительно проверены тестами, а Swift queue/DTO harness проверяет progress events, повтор после ошибки и уникальную identity фрагментов.

## Финальное ревью SA-04

- Production `mac_bridge.dispatch` запускался на отдельной временной тестовой папке и временной SQLite базе (без подмены extractor/indexer). В папке были TXT, текстовый PDF и DOCX с заголовком раздела. Первая синхронизация обработала 3 файла; поиск вернул PDF страницу 1 и DOCX heading `Production Heading`. После изменения TXT/PDF и удаления DOCX повторная синхронизация обработала 2 изменённых файла, удалила 1 запись, убрала старые совпадения и нашла новый текст. Корпус и база удалены временным каталогом после теста. OCR inference не требовался: PDF содержал достаточный текстовый слой.
- `index_status.issues` проверен после повторного открытия SQLite: сохранённые ошибки/предупреждения доступны вместе со счётчиками. Регрессионные тесты проверяют persisted issue в Python indexer и bridge.
- Swift harness проверяет сохранение технического кода отдельно от пользовательского описания, блокировку progress после `.cancelling`/`.cancelled`, сохранённые issue DTO и уникальные identity для страниц PDF.

## Дополнительный ручной UI QA

- В отдельной копии приложения с отдельным bundle ID переключил и визуально осмотрел Settings в светлой и тёмной теме; обе темы отрисовались. В Library виден источник с сохранённым предупреждением («Проблемы обработки: 1», «Готово с предупреждениями»). Основные настройки пользователя и папки не менялись.
- Не удалось завершить проверку малого размера окна и запустить через row menu живую backend error/cancel операцию: после нескольких наблюдений CUA перестал доставлять клики в окно (`noWindowsAvailable`/ошибка ScreenCaptureKit `-3811`). Реальные screenshots не сохранены как файлы.
- VoiceOver и macOS 14 также не проверены. Локальная сборка выполнена на macOS 27 SDK, deployment target 14.

## Ограничения визуального QA

Окна приложения осмотрены через CUA screenshot/accessibility API, но доступный screenshot API возвращает изображение только для просмотра в сессии и не предоставляет сохранение в репозиторий. Поэтому в эту папку не добавлены бинарные скриншоты и не сделаны искусственные изображения. Полноразмерные снимки для светлой/тёмной темы, состояния progress/cancel, warning и поиска остаются ручным QA пунктом.

Экранный сценарий использовал тестовый bridge с синтетическими ответами для проверки отображения источников. Он не заменяет сквозную ручную проверку упакованного production backend на реальных разрешённых материалах. См. точные результаты и непроверенные сценарии в [testing.md](../../wiki/development/testing.md).
