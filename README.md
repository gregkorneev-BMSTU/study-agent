# Study Agent

Локальный агент для поиска и анализа учебных материалов. Цель проекта — настольное приложение для Windows и macOS, которое создаёт персональную базу знаний из выбранных пользователем документов и отвечает на вопросы со ссылками на первоисточники.

> **Статус:** ранний каркас для разработчиков. Пользовательский интерфейс, автоматическая индексация, OCR, локальные модели, RAG и установщики пока не реализованы. Клонирование репозитория сейчас не устанавливает готовое приложение.

## Что планируется

- Подключение одной или нескольких локальных папок через интерфейс.
- Автоматическое индексирование после добавления папки, отслеживание изменений и отчёт о ходе обработки.
- Извлечение текста из документов; Chandra OCR для сканов, изображений и рукописей.
- Локальные эмбеддинги и Qwen для семантического поиска и ответов RAG.
- Ответы только на основании найденных материалов, с названиями документов, фрагментами и страницами. Если данных недостаточно, приложение сообщит об этом.
- Разделы «Поиск» и «Библиотека», кроссплатформенная упаковка для Windows и macOS.
- Дополнительно — выбранные пользователем материалы каталога IU5Hub и ограниченные MCP-инструменты.

## Что уже есть

- Python-пакет `study_agent` и базовая конфигурация разработки.
- Read-only источник локальной папки для файлов `.txt` и `.md`. Корень задаётся параметром; личные пути не вшиты в исходники.
- CI с проверками pytest и Ruff на Python 3.12 и 3.13.
- Архитектурная документация и поэтапный план реализации.

Пока нет интерфейса или команды запуска готового агента. Текущая реализация предназначена для разработки и проверки основы.

## Установка для разработки

Требуется Python 3.12 или новее.

```sh
git clone https://github.com/gregkorneev-BMSTU/study-agent.git
cd study-agent
python3.12 -m venv .venv
```

Активируйте окружение:

```sh
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Установите зависимости разработки и запустите проверки:

```sh
python -m pip install '.[dev]'
pytest
ruff check .
```

Эти команды проверяют каркас проекта; они не запускают настольное приложение, не загружают модели и не индексируют документы.

## Скачать Qwen для локальной проверки

Установка Qwen необязательна для разработки текущего каркаса. Для RAG-экспериментов на компьютере с 24 ГБ памяти рекомендуем проверить `qwen3.5:9b`; для более широкого диапазона пользовательских компьютеров предусмотрите лёгкий вариант `qwen3.5:4b`.

- **macOS:** установите Ollama с [официальной страницы](https://ollama.com/download), откройте приложение, затем в Terminal выполните `ollama pull qwen3.5:9b` (или `ollama pull qwen3.5:4b` для меньшего варианта).
- **Windows:** установите Ollama с [официальной страницы](https://ollama.com/download/windows), затем в PowerShell выполните `ollama pull qwen3.5:9b` (или `ollama pull qwen3.5:4b` для меньшего варианта).

На обеих платформах проверить загрузку можно командами `ollama list` и `ollama run qwen3.5:9b` (или выбранный вариант `4b`). Модель скачивается в хранилище Ollama, отдельно от проекта; 9B занимает около 6.6–7.6 ГБ, 4B — 3.3–4.0 ГБ. Установка модели пока не подключает её к приложению. Подробная пошаговая инструкция и требования к ОС — в [Wiki: установка моделей](wiki/model-setup.md).

## Локальные данные и конфиденциальность

Приложение проектируется так, чтобы пользователь сам выбирал папки с материалами. Код не должен зависеть от путей разработчика. Исходные документы, индексы, кэш и модели не следует добавлять в Git. Тестовые данные должны быть синтетическими или обезличенными.

Целевой режим обработки документов и генерации ответов — локальный. Внешние облачные LLM и OCR API не должны использоваться как скрытый fallback. При первом получении моделей может потребоваться сеть; работа с уже подготовленной локальной библиотекой должна быть офлайн. Подробности и открытые технические решения см. в Wiki.

## План разработки

1. Портативный локальный поток: выбрать папку, извлечь текст, сохранить локальный индекс, найти фрагмент и показать источник.
2. Добавить форматы документов и проверить Chandra OCR на сканах, русском тексте, рукописях, таблицах и формулах.
3. Подключить локальные эмбеддинги и Qwen/RAG с отказом от неподтверждённых ответов.
4. Создать интерфейс «Поиск» и «Библиотека», затем проверить сборку и установку на Windows и macOS.
5. Реализовать дополнительные источники и MCP-инструменты после стабилизации основного потока.
