# Инструкции для Codex

Проект готовит основу локального агента для поиска и анализа учебных материалов. Перед крупной задачей прочитайте `wiki/development/requirements.md`, `wiki/development/architecture.md` и `wiki/development/current-state.md`; после изменения обновите соответствующие страницы Wiki.

## Работа

- Начинайте с одного исполнителя. Делегируйте независимые исследования или проверки только при реальной выгоде; не более трёх параллельных специалистов.
- Роли: **Orchestrator** согласует архитектуру, интегрирует и проверяет изменения, обновляет Wiki и отвечает за Git; **Architecture Agent** исследует контракты и ADR; **AI / Backend Agent** занимается Python, локальным поиском, моделями, MCP и источниками; **Frontend Agent** — интерфейсом; **QA / Security Agent** — тестами, безопасностью и производительностью.
- Назначайте каждому специалисту конкретный результат и отдельный набор файлов. Специалисты не коммитят и не публикуют изменения.
- Используйте установленную Codex возможность субагентов, если она предоставлена текущей сессией. Роли выше — инструкции делегирования, а не отдельные фоновые службы.
- Не реализуйте полный RAG, не загружайте модели и не отправляйте пользовательские документы во внешние сервисы без явного разрешения.

## Качество и Git

- Держите реализацию минимальной, используйте type hints и локальные зависимости проекта.
- Запускайте `pytest` и `ruff check .` перед завершённым изменением; не заявляйте о проверках, которых не запускали.
- Не изменяйте и не связывайте проект с репозиторием `iu5hub`; используйте его только как внешний источник для отдельного адаптера.
- По умолчанию работа Codex ведётся непосредственно в `main`; не создавайте и не используйте `beta`. Если конкретная задача явно задаёт рабочую ветку и Pull Request, соблюдайте её процесс для этой задачи.
- Не переписывайте историю и не используйте force push. Проверяйте индексируемые файлы перед `git add`; Orchestrator коммитит и публикует проверенные изменения в целевую ветку согласно процессу, заданному текущей задачей.
