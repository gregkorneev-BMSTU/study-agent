## Models and their outputs

An Ollama runtime license does not license every model downloaded through Ollama. The user is responsible for reviewing the license of each selected model.

Chandra 2's weights are not MIT-licensed. In the pinned Modified OpenRAIL-M text, Attachment A restricts use of the model, its derivatives, **and outputs** for organizations/entities above the stated $2 million prior-year revenue or total-funding thresholds (except personal/research use), and for products/services competing with Datalab or its affiliates. The license also requires attribution and, in clause 8, says its Share-a-Like terms apply to model outputs and their derivatives. Datalab's Chandra README separately says commercial self-hosting requires a license. These terms are not a blanket commercial-use grant.

That output language matters for OCR because extracted text can reproduce material supplied by the user. Study Agent does not determine how the model-output clause interacts with rights in a user's source documents or third-party content. Review the exact license and document rights, and ask Datalab or qualified counsel where applicability is uncertain. The project grants no extra model or output rights.

`assets/StudyAgent_Apple_Icon_Kit/` contains PNG, ICNS, SVG, and preview files but currently has no license/provenance statement identifying the rights holder or source of every layer. ## Distribution checks

- The macOS build script places the Study Agent `LICENSE`, this notice, the PSF Python license, and package license texts found in the build environment under `Study Agent.app/Contents/Resources/Legal/`. It also records that environment's resolved Python package versions/license metadata in `PYTHON_BUILD_ENVIRONMENT.csv`. This inventory can include build-only packages and is not proof that every listed package is inside the app; inspect the PyInstaller bundle and verify the legal folder for every release. The current native macOS bundle audit found PyTorch, Torchvision, NumPy, pypdfium2, and Hugging Face libraries; it did not find PySide6 or the `chandra` Python import package.
- The Windows WinUI client does not use PySide6. Its backend ZIP is built from the installed Windows packaging environment; `scripts/package_windows_backend.py` includes project notices and license/notice/copying files discoverable in installed wheel metadata. This generated inventory must still be audited against the actual PyInstaller output and wheel licenses before distribution; it is not a substitute for a reviewed SBOM. The unsigned Windows MSIX and its third-party notices have not yet been built or inspected.
- PyInstaller collects modules based on the helper's imports. A resolved requirements file or Software Bill of Materials should be reviewed for each release because dependency versions and transitive components can change within the declared ranges.
- The Beta 1 and Beta 2 archives predate this licensing documentation and are not retroactively modified. New builds must be checked against the component versions they actually contain.
