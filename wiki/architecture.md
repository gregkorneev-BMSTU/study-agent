# Архитектура

## Направление

Приложение строится как локальная Python-логика с независимым UI. Границы источников, индексации, поиска, генерации и выполнения инструментов описываются отдельными контрактами; на первом этапе это документация, а не готовая иерархия классов.

```text
UI (решение отложено)
        │
QueryRouter ── обычный поиск ── MaterialRetriever ── VectorStore
        │                                  ▲
        ├── RAG ── AnswerGenerator         │
        └── AgentExecutor ── MCPTools      │
                                           │
DocumentIndexer ◀── DocumentSource ── LocalFolderSource
                                └────── IU5HubSource
```

Документы после явного выбора пользователя поступают в индексатор; извлечение и поиск должны сохранять метаданные для ссылок на исходный файл. Маршрутизатор выбирает простой поиск, RAG или действие. Долгоживущие процессы модели и инструменты остаются локальными, если пользователь отдельно не разрешил сетевой источник.

## IU5Hub

Публичный GitHub `gregkorneev/iu5hub` — внешний каталог, а не зависимость или подмодуль этого проекта. Текущая проверенная структура — TypeScript-приложение с `MaterialsRepository`, каталогом курсов и отдельным доступом к публичным папкам Яндекс.Диска. Адаптер Python должен обращаться к документированному/проверенному внешнему контракту и преобразовывать его в собственные DTO; не импортировать исходники iu5hub и не изменять его репозиторий. Сетевой доступ нужен для просмотра каталога и получения выбранного материала; офлайн режим относится к уже выбранным и проиндексированным данным.

## Технические кандидаты и риски

Python — основной язык. Ollama и Qwen3 4B/8B, локальная модель эмбеддингов, Chroma, LangGraph и MCP Python SDK/FastMCP — предварительные кандидаты, не обязательные зависимости текущего каркаса. На 24 ГБ общей памяти стартовый ориентир для будущего замера — Qwen3 4B с коротким/умеренным контекстом; память под контекст, ОС, UI и эмбеддинги должна измеряться совместно. Сравните качество и память до выбора 8B.

Храните бэкенды и зависимости необязательными до выбора конкретного потока. Для небольшой библиотеки сложная агентная оркестрация и GraphRAG не предполагаются без измеримой пользы. Кроссплатформенность требует ранней проверки файловых путей, нативных зависимостей векторного хранилища и упаковки UI.
