# Архитектура

## Целевая схема

Настольное приложение для Windows и macOS разделяет интерфейс, доменную логику и системные интеграции. UI-фреймворк ещё не выбран. Python остаётся основным языком ядра; интерфейс не должен владеть логикой индексации и поиска.

```text
Desktop UI (Поиск / Библиотека)
             │
      Application services
             │
      QueryRouter ── простой поиск ──────────────┐
         │                                       │
         ├── RAG ── локальная Qwen               │
         └── AgentExecutor ── MCP tools          │
                                                 ▼
DocumentIndexer ── Extractors ── Chunker ── Embeddings ── LocalStore
       ▲                 ▲                               │
       │                 ├── text-layer extractors       │
       │                 └── Chandra OCR (scans/images)  │
       │                                                 │
DocumentSource ── LocalFolderSource / IU5HubSource ── MaterialRetriever
```

Поток источника: пользователь выбирает источник → приложение перечисляет документы → извлекает текст и метаданные → при необходимости запускает локальный OCR → формирует фрагменты/эмбеддинги → записывает индекс → поиск/ответ возвращают ссылки на эти же записи.

## Границы компонентов

- **DocumentSource** перечисляет документы и предоставляет выбранное содержимое; каждый источник имеет стабильный локальный ID.
- **Extractors** выбирают обработчик формата. Текстовый слой извлекается напрямую; Chandra вызывается для сканированных/графических страниц. Оригинал не меняется.
- **DocumentIndexer** отслеживает версии/хеши, извлекает метаданные, делит текст, создаёт эмбеддинги и сохраняет состояние/ошибки. Индексация после добавления выбранной папки автоматическая; обновления инкрементальные.
- **LocalStore** хранит локальные документы, страницы, фрагменты, эмбеддинги и состояние библиотеки. Конкретная БД ещё не закреплена.
- **MaterialRetriever** выполняет поиск и возвращает найденный текст вместе с исходным ID и метаданными страницы.
- **QueryRouter** направляет запрос в обычный поиск, RAG или действие. Простой поиск не должен вызывать LLM.
- **AnswerGenerator** использует выбранную пользователем локальную языковую модель, ограничивая контекст найденными фрагментами. Модель и runtime задаются настройками приложения, а не константами в коде; отсутствие доказательств должно приводить к отказу от ответа.
- **AgentExecutor/MCPTools** появятся после проверки основных сценариев; инструменты должны иметь явные ограничения доступа и подтверждение для действий с побочными эффектами.
- **UI** реализован на PySide6: разделы «Поиск», «Библиотека» и «Настройки». Визуальный язык использует полупрозрачные слои, мягкие границы и системную типографику в эстетике Liquid Glass. Оформление общее для обеих ОС и не зависит от macOS-only API; настройки пользователя хранятся через `QSettings`.

## Переносимость и хранение данных

- Корневые пути передаются источнику во время работы, а не вшиваются в код.
- Локальная конфигурация хранит ID источника и выбранный корень. В индексных записях использовать ID + путь относительно корня; абсолютный путь может храниться в локальном состоянии для доступа к исходнику, но не попадать в Git.
- БД, OCR-производные, эмбеддинги, модели, логи и кэш располагаются в пользовательской директории приложения, отдельно от checkout.
- Для пользователей GitHub установка и запуск не требуют знать настройки автора. Платформенные пути получают через стандартные API, не конкатенируют строками.
- Выключение/перемещение источника должно показывать понятный статус; удаление источника очищает его производные записи, но не исходные пользовательские файлы.
- Тестовые фикстуры синтетические; не включать данные из персонального каталога или скрытую карту источников.

## Локальные модели и граница сети

Qwen, OCR Chandra и модель эмбеддингов запускаются локально. Первичная загрузка модели может требовать сети, но обработка пользовательских документов по умолчанию остаётся локальной. Сетевой Chandra API не использовать без отдельного явного разрешения пользователя. Каталог IU5Hub является отдельным внешним источником: сеть нужна только для просмотра/получения выбранных материалов, после локальной индексации они доступны офлайн.

### Настраиваемая языковая модель

- Приложение не должно быть привязано к размеру, имени или тегу одной модели. `AnswerGenerator` получает модель через конфигурацию/провайдер runtime; имя модели, например `qwen3.5:4b` или `qwen3.5:9b`, хранится в пользовательских настройках вне репозитория.
- При первом запуске можно предложить 4B как более лёгкую стартовую модель. Пользователь может выбрать другую совместимую локальную модель, если она установлена; настройки должны сообщать, если выбранной модели нет, и позволять загрузить её отдельно.
- Основной профиль разработки и приёмочные проверки качества ориентируются на 4B, если целевые компьютеры будут ограничены ресурсами. 9B используется как дополнительный сравнительный профиль на более мощном оборудовании, а не как единственный критерий готовности.
- Формат настроек не должен раскрывать пользовательские документы или локальные пути в Git. Если используется Ollama, интеграционный слой изолирует его конкретный API от `AnswerGenerator`, чтобы позднее можно было добавить другой локальный runtime без переписывания логики ответа.
- Поддерживаемые модели и минимальные требования фиксируются после замеров качества, скорости и памяти на Windows/macOS; размер весов на диске не считается полным расходом оперативной/общей памяти.

Chandra — целевой OCR-компонент, однако пригодность локального режима, качество русской печати/рукописи, таблиц и формул, скорость и память необходимо проверить на обеих целевых ОС до фиксации как обязательной зависимости. Лицензии кода и весов оцениваются отдельно.

## IU5Hub

Публичный GitHub `gregkorneev/iu5hub` — внешний каталог, не зависимость, подмодуль или часть исходников этого проекта. `IU5HubSource` преобразует проверенный внешний контракт в собственные DTO. Исходники iu5hub не импортировать и тот репозиторий не изменять. Внешние материалы становятся локальными только по выбору пользователя и после успешной загрузки.

## Кандидаты и риски

Предварительные кандидаты: Python 3.12+, PySide6, Qwen3.5 4B через Ollama как основной профиль разработки и 9B как сравнительный профиль на машине 24 ГБ (см. [установку моделей](model-setup.md)), локальная модель эмбеддингов, Chroma/SQLite для хранения. Зависимости и требования ещё требуют измерений на Windows/macOS. Сравнивать полную нагрузку (модель, контекст, UI, индекс и OCR), а не размер весов.

Для первого корпуса 10–100 документов не вводить GraphRAG и тяжёлую оркестрацию без измеримой пользы. Текущий поиск ранжирует совпадения слов в TXT/Markdown; Ollama вызывается через `127.0.0.1` и получает только вопрос и найденные выдержки. Windows не считать подтверждённой до отдельного прогона.
