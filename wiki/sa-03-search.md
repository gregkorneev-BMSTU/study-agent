# SA-03: поиск через приложение

Локальная реализация на ветке `feature/sa-03-rag`, 2026-10-26. По новому указанию пользователя доступны изменения UI и полный сквозной поиск; коммиты остаются локальными, push/PR/merge не выполняются. Это развитие [первых трёх шагов](sa-03-embeddings.md), не новый опубликованный релиз.

## Проверка пользователем

Из корня проекта:

```sh
source .venv/bin/activate
APP_OUTPUT_DIR="$PWD/dist/sa-03" ./scripts/build_macos_native_app.sh
open "dist/sa-03/Study Agent.app"
```

Для запуска Python UI-прототипа: `python -m study_agent`. Сборка macOS требует `.[packaging]` и Xcode. OCR остаётся optional: сборка без `.[ocr]` не включает Chandra runtime и не предназначена для проверки сканов.

1. Открыть настройки и обновить список моделей. В разделе «Поиск по материалам» выбрать `qwen3-embedding:0.6b` (или другую установленную embedding-модель); размерность определяется из локального `/api/show`. В текущей сессии пользователь явно разрешил загрузку этой модели, и она установлена в Ollama. Приложение само веса не загружает.
2. Выбрать режим «Гибридный» или «По смыслу». Префиксы зависят от модели, по умолчанию пусты. Для Qwen можно отдельно проверить instruction/query prefix из документации модели; на приведённом синтетическом корпусе пустой префикс тоже работал.
3. Добавить папку в библиотеку. Для уже подключённых папок нажать «Подготовить семантический индекс». Прогресс отображается в библиотеке; нативный клиент показывает количество готовых векторов.
4. Для ответа выбрать установленную локальную языковую модель. В этой сессии проверена `gemma4:e2b`, уже присутствовавшая в Ollama; embedding-модель и chat-модель выбираются отдельно. Нативный клиент позволяет выбрать поиск без ответа; в PySide6 есть отдельная кнопка поиска фрагментов.
5. Задать вопрос. Для воспроизводимости можно создать Markdown-файлы из `tests/fixtures/rag_corpus.json`; в текущем рабочем каталоге копия такого корпуса подготовлена в игнорируемом `dist/sa-03-demo/`. Пример: «Как называется прямоугольный массив чисел?» → `matrix.md`. Контроль нехватки информации: «Какова цена биткоина сегодня?» → отказ без источников.

Удаление embedding-модели не удаляет индекс. Лексический поиск работает без embedding runtime; текстовая фаза синхронизации фиксируется даже при последующей ошибке эмбеддингов. Смена digest/размерности/префиксов требует подготовки соответствующего профиля. При неполном покрытии выдача отмечает `embedding_pending`, UI предлагает подготовку индекса. Автоматического file watcher нет: изменения подхватываются штатной синхронизацией/проверкой изменений.

## Backend и ранжирование

`retrieval.retrieve(storage, source_ids, query, mode, embedder, ...)` возвращает `RetrievalResult(hits, embedding_pending)`. Публичный `SearchHit` сохранён: ID источника/фрагмента, относительный путь, текст, page/heading/marker. Вектор и связанный текст читаются одним SQLite snapshot; хеш полного входа защищает от устаревшего вектора. Поиск не запускает извлечение документов или построение document embeddings; вычисляется только query embedding.

- `lexical`: существующий SQLite FTS5/BM25, fallback при отсутствии FTS5.
- `semantic`: точный перебор нормализованных float32-векторов и cosine similarity. Текущий минимальный cosine — 0.35; это начальная эвристика, а не доказательство релевантности. Нет ANN или отдельного векторного сервера. Стоимость растёт с числом фрагментов и размерностью.
- `hybrid`: reciprocal-rank fusion, `k=60`, равные веса lexical/vector по умолчанию. Параметры `lexical_weight` и `min_similarity` доступны в Python API для измерений. Шкалы BM25/cosine не складываются напрямую.

Получаем до 32 кандидатов минимум (либо `limit*4`), затем исключаем идентичные/сильно перекрывающиеся фрагменты одного документа; наружу до 8 hits. Для JSONL совместимости `score` остаётся целым: cosine/RRF масштабируются на 1 000 000. Его абсолютные значения между режимами не сравниваются.

`rag.generate_answer` ограничивает контекст пятью источниками и 5000 UTF-8 bytes с метаданными; вопрос — 1024 UTF-8 bytes. Эти ограничения не являются точным tokenizer budget. В Ollama заданы `num_ctx=8192`, `num_predict=768`, `temperature=0`. Пустые и состоящие только из Markdown-заголовков snippets в контекст не включаются; обрезанный текст сохраняется в возвращаемых sources. Генератор получает названия/относительные пути/page/heading, но не абсолютные пути папок.

Приложение передаёт в `answer` корни, запрос и профиль. Backend повторно выполняет retrieval из SQLite, игнорируя клиентские `hits`. Источники строятся из этих записей, не из названий, придуманных LLM. Модель может вернуть `INSUFFICIENT_CONTEXT`; при отсутствии контекста модель вообще не вызывается. Ответ должен содержать номера существующих источников и ссылки в каждом содержательном абзаце. Неизвестные номера, отсутствующие цитаты и выдуманные URL/Markdown-links отклоняются с `invalid_citations`, сохраняя поисковую выдачу. Возвращаются только процитированные sources; их номера и текст ответа перенумеровываются вместе. Независимая выдача UI не имеет номеров цитат, чтобы её не путали с источниками ответа.

`grounded=true` означает прохождение структурной проверки ссылок; это **не автоматическое доказательство истинности каждого утверждения**. Отказ модели и релевантность требуют дальнейшей приёмки на разрешённых учебных данных.

Транспорт embeddings и генерации фиксирован на loopback, игнорирует HTTP proxies и запрещает redirects. Проверяются установленный digest, capability и remote metadata `/api/show`, включая remote aliases. Облачного fallback нет. Отмена индексирующего helper завершает процесс; сохранённые batch переживают повторный запуск.

Для QA доступен необязательный `STUDY_AGENT_DATA_DIR`: он меняет только путь SQLite. В штатном запуске действует прежний пользовательский каталог; переменная не требуется для использования приложения. UI-настройки macOS и PySide6 хранятся своими платформенными механизмами.

## Воспроизводимые измерения

```sh
.venv/bin/python scripts/benchmark_retrieval.py \
  --model qwen3-embedding:0.6b --dimensions 1024 \
  --output /tmp/sa03-benchmark.json
```

Скрипт создаёт временные документы/SQLite из синтетической fixture, не скачивает модели и не читает пользовательские папки. `--query-prefix` и `--document-prefix` позволяют сравнить подготовку входа. Результаты текущей машины: [QA отчёт](../artifacts/sa-03-search-qa/README.md). Для реального сравнения второй модели нужно отдельное явное разрешение на её загрузку. Windows, большие корпуса и качество OCR не проверены; готовность всего Issue #3 зависит от дальнейшей приёмки, а не только от наличия рабочего приложения.
