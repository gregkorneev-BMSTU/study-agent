В локальной `codex/sa03-answer-scroll-tests` встроенный WKWebView передаёт вертикальные wheel/trackpad события внешнему NSScrollView. Его документ уже растянут по содержимому, поэтому вертикальная прокрутка принадлежит списку результатов; раньше WebKit поглощал событие. ## Исправление пустых карточек и повтор ответа — 2026-10-27

Текст чанка остаётся видимым до успешной загрузки Markdown/LaTeX. WebKit показывается только после подтверждённого непустого DOM и измерения высоты. Ошибки JS, загрузки, завершение web process и таймаут 8 секунд оставляют выделяемый исходный текст. Явно задана доступная ширина; initial text устанавливается до загрузки страницы. Проверки включают настоящий SwiftUI NSHostingView, а не только отдельный WKWebView. Это закрывает пустой UI при сбое renderer; точная причина первоначального пользовательского снимка однозначно не установлена.

После ошибки ссылок backend делает одну повторную генерацию на тех же материалах с уточнением формата. Результат снова проходит все проверки; ссылки автоматически не добавляются. Источники с `source_quality` не запускают повтор. Повтор использует `think:false`, чтобы получить краткий ответ в пределах лимита, см. [официальный API Ollama](https://github.com/ollama/ollama/blob/main/docs/capabilities/thinking.mdx). При повторной неудаче остаётся конкретная ошибка и доступные материалы.

## Карточки macOS — 2026-10-27

Продолжение UI находится в локальной ветке `codex/sa03-markdown-cards`, созданной от `feature/sa-03-rag`. Ответ отображается как Markdown с LaTeX без отдельного переключателя исходного текста. Источники имеют компактный заголовок: имя файла, путь и раскрываемый Original Text. У источников ответа он свёрнут, у поисковых результатов открыт. Внутри отображается полный сохранённый чанк (`full_excerpt`, fallback `excerpt`), включая соседний материал, а не только формула, выбранная для контекста модели. Оригиналы и размер контекста модели не изменяются; повторная индексация для этого поля не нужна.

Офлайн renderer поддерживает заголовки, абзацы, выделение, списки, цитаты, pipe-таблицы и код. LaTeX и code spans защищаются до обработки Markdown: underscores и пустые строки внутри display-формул сохраняются. Это ограниченное подмножество Markdown; вложенные списки пока плоские, ссылки/изображения и HTML остаются буквальным текстом. Нет CDN, HTML из документов не исполняется. Qt-прототип сохраняет прежнее Unicode-представление.

Локальная реализация на ветке `feature/sa-03-rag`, 2026-10-26. По новому указанию пользователя доступны изменения UI и полный сквозной поиск; коммиты остаются локальными, push/PR/merge не выполняются. Это развитие [первых трёх шагов](sa-03-embeddings.md), не новый опубликованный релиз.

## Проверка пользователем

Из корня проекта:

```sh
source .venv/bin/activate
APP_OUTPUT_DIR="$PWD/dist/sa-03" ./scripts/build_macos_native_app.sh
open "dist/sa-03/Study Agent.app"
```

Для запуска Python UI-прототипа: `python -m study_agent`. Сборка macOS требует `.[packaging]` и Xcode. OCR остаётся optional: сборка без `.[ocr]` не включает Chandra runtime и не предназначена для проверки сканов.

1. Открыть настройки и обновить список моделей. В разделе «Поиск по материалам» выбрать `qwen3-embedding:0.6b` (или другую установленную embedding-модель); размерность определяется из локального `/api/show`. В текущей сессии пользователь явно разрешил загрузку этой модели, и она установлена в Ollama. Приложение само веса не загружает.
2. Выбрать режим «Гибридный» или «По смыслу». Префиксы зависят от модели, по умолчанию пусты. Для Qwen можно отдельно проверить instruction/query prefix из документации модели; на приведённом синтетическом корпусе пустой префикс тоже работал.
3. Добавить папку в библиотеку. Для уже подключённых папок нажать «Подготовить семантический индекс». Прогресс отображается в библиотеке; нативный клиент показывает количество готовых векторов.
4. Для ответа выбрать установленную локальную языковую модель. В этой сессии проверена `gemma4:e2b`, уже присутствовавшая в Ollama; embedding-модель и chat-модель выбираются отдельно. Нативный клиент позволяет выбрать поиск без ответа; в PySide6 есть отдельная кнопка поиска фрагментов.
5. Задать вопрос. Для воспроизводимости можно создать Markdown-файлы из `tests/fixtures/rag_corpus.json`; создайте отдельную тестовую папку: в существующий `dist/sa-03-demo/` уже могли быть добавлены пользовательские материалы, поэтому его нельзя считать полностью синтетическим. Пример: «Как называется прямоугольный массив чисел?» → `matrix.md`. Контроль нехватки информации: «Какова цена биткоина сегодня?» → отказ без источников.

Удаление embedding-модели не удаляет индекс. Лексический поиск работает без embedding runtime; текстовая фаза синхронизации фиксируется даже при последующей ошибке эмбеддингов. Смена digest/размерности/префиксов требует подготовки соответствующего профиля. При неполном покрытии выдача отмечает `embedding_pending`, UI предлагает подготовку индекса. Автоматического file watcher нет: изменения подхватываются штатной синхронизацией/проверкой изменений.

## Backend и ранжирование

`retrieval.retrieve(storage, source_ids, query, mode, embedder, ...)` возвращает `RetrievalResult(hits, embedding_pending)`. Публичный `SearchHit` сохранён: ID источника/фрагмента, относительный путь, текст, page/heading/marker. Вектор и связанный текст читаются одним SQLite snapshot; хеш полного входа защищает от устаревшего вектора. Поиск не запускает извлечение документов или построение document embeddings; вычисляется только query embedding.

- `lexical`: существующий SQLite FTS5/BM25, fallback при отсутствии FTS5.
- `semantic`: точный перебор нормализованных float32-векторов и cosine similarity. Минимальный cosine по умолчанию — 0.65; порог эвристический и настраиваемый. Нет ANN или отдельного векторного сервера. Стоимость растёт с числом фрагментов и размерностью.
- `hybrid`: reciprocal-rank fusion, `k=60`, равные веса lexical/vector по умолчанию. Параметры `lexical_weight` и `min_similarity` доступны в Python API для измерений. Шкалы BM25/cosine не складываются напрямую.

Получаем до 32 кандидатов минимум (либо `limit*4`), затем исключаем идентичные/сильно перекрывающиеся фрагменты и группируем совпадения одного документа и раздела (без заголовка — страницы/маркера). Наружу до 8 hits; `related_count` показывает число скрытых кандидатов группы, а не все совпадения во всём документе. Для JSONL совместимости `score` остаётся целым: cosine/RRF масштабируются на 1 000 000. Его абсолютные значения между режимами не сравниваются.

Для узких математических запросов дополнительная эвристика различает, например, корень из x, обратный корень и степени. При наличии точного совпадения конфликтующие формулы отбрасываются. Из таблицы выбирается целая display-формула как буквальная подстрока исходного текста; непосредственно соседние условия и оговорки сохраняются. Код не превращается в формулу или утверждение. Это ограниченные правила для распространённых записей, не универсальный математический поиск.

`quality_warnings: ["formula_suspect"]` отмечает узкие признаки повреждения: несбалансированные delimiters/braces, `sqrt{dx}`, ошибочную обычную степенную формулу для `sqrt{x^n}`. Такие выдержки видны с предупреждением, но исключаются из контекста ответа. Если чистого контекста нет, возвращается `source_quality` без вызова модели. Эвристики не проверяют истинность произвольных формул и не исправляют оригиналы.

SwiftUI отображает формулы через встроенный офлайн KaTeX с MathML, без CDN и загрузки внешнего содержимого. Original Text раскрывает полный чанк с Markdown и LaTeX. В Qt предусмотрено упрощённое Unicode-представление; неподдержанные команды сохраняются. Оба клиента оставляют код буквальным. Лицензии JS/CSS и шрифтов находятся в `assets/math/` и включаются в macOS app.

Markdown processing version повышена до 2: display-формулы с пустыми строками сохраняются целиком в пределах ограничения размера фрагмента. Для существующей библиотеки нажмите «Проверить изменения»: обновятся Markdown-фрагменты и их эмбеддинги; версия обработки PDF/DOCX не меняется.

`rag.generate_answer` ограничивает контекст пятью источниками и 5000 UTF-8 bytes с метаданными; вопрос — 1024 UTF-8 bytes. Эти ограничения не являются точным tokenizer budget. В Ollama заданы `num_ctx=8192`, `num_predict=2048`, `temperature=0`; prompt явно требует ссылку в каждом абзаце, пункте списка и отдельной формуле. Пустые и состоящие только из Markdown-заголовков snippets в контекст не включаются; обрезанный текст сохраняется в возвращаемых sources. Генератор получает названия/относительные пути/page/heading, но не абсолютные пути папок.

Приложение передаёт в `answer` корни, запрос и профиль. Backend повторно выполняет retrieval из SQLite, игнорируя клиентские `hits`. Источники строятся из этих записей, не из названий, придуманных LLM. Модель может вернуть `INSUFFICIENT_CONTEXT`; при отсутствии контекста модель вообще не вызывается. Ответ должен содержать номера существующих источников и ссылки в каждом содержательном абзаце. Неизвестные номера, отсутствующие цитаты и выдуманные URL/Markdown-links отклоняются с `invalid_citations`, сохраняя поисковую выдачу. Возвращаются только процитированные sources; их номера и текст ответа перенумеровываются вместе. Независимая выдача UI не имеет номеров цитат, чтобы её не путали с источниками ответа.

`grounded=true` означает прохождение структурной проверки ссылок; это **не автоматическое доказательство истинности каждого утверждения**. Отказ модели и релевантность требуют дальнейшей приёмки на разрешённых учебных данных.

При `invalid_citations` UI объясняет конкретную причину: `missing_citations`, `unknown_source`, `uncited_paragraph`, `generated_links` или `source_quality`. Технические детали содержат стадию `answer`, модель, число источников и при необходимости неверные номера, номер абзаца или коды предупреждений. Это отказ от показа непроверенного ответа после успешного поиска; найденные выдержки остаются доступны. Исходный ответ модели и тексты документов в диагностические поля не попадают. Ссылки вида `[1, 2]` поддерживаются; числа внутри кода и LaTeX не считаются ссылками. Отдельный блок формулы/кода может наследовать ссылку соседнего абзаца.

Транспорт embeddings и генерации фиксирован на loopback, игнорирует HTTP proxies и запрещает redirects. Проверяются установленный digest, capability и remote metadata `/api/show`, включая remote aliases. Облачного fallback нет. Отмена индексирующего helper завершает процесс; сохранённые batch переживают повторный запуск.

Генерация задаёт нулевые `presence_penalty` и `frequency_penalty` и нейтральный `repeat_penalty=1`, чтобы настройки в Modelfile отдельных моделей не мешали повторять source labels. Валидатор разрешает короткий заголовок/подпись перед содержательным ответом без citation; фактические абзацы, пункты и формулы остаются под проверкой. Сквозной Qwen 3.5 4B тест обнаружил, что фраза «Вот таблица интегралов из материала:» ранее считалась несосланным фактическим абзацем и запускала repair, хотя каждая формула имела правильную ссылку. После исправления этот ответ проходит без повторной генерации.

Для QA доступен необязательный `STUDY_AGENT_DATA_DIR`: он меняет только путь SQLite. В штатном запуске действует прежний пользовательский каталог; переменная не требуется для использования приложения. UI-настройки macOS и PySide6 хранятся своими платформенными механизмами.

## Группировка файлов и контекст соседних чанков — 2026-10-28

Для выдачи одна карточка соответствует одному файлу. Поле `matched_excerpts` содержит все фрагменты, которые прошли retrieval, и показывается в `Original Text`, который по умолчанию закрыт. К генератору ответа передаются совпавшие фрагменты и соседние чанки в пределах того же документа. Соседние чанки добавляют связность объяснению, но не отображаются как найденные совпадения. `min_similarity` настраивается в диапазоне 0–1 и по умолчанию равен 0.65; в гибридном режиме семантический порог фильтрует приблизительные лексические кандидаты, а точные совпадения запроса сохраняются.

Совпавшие фрагменты внутри файла упорядочиваются по сохранённому `chunks.ordinal`, независимо от ранга совпадения; сам основной hit по-прежнему выбирается по релевантности. При преобразовании результата retrieval обязан передавать `ordinal` из SQLite в `SearchHit`: без этого значения сортировка сохраняла порядок ранжирования. Регрессионный тест проверяет полный путь retrieval на результатах, намеренно возвращённых в обратном порядке. На macOS источник ответа не дублирует карточку поиска: цитатный номер ставится на единственную карточку этого файла, а все совпавшие чанки внутри неё идут по исходному порядку.

## Уточнение порога и карточек — 2026-10-28

Порог по умолчанию повышен с 0.35 до 0.65: старое значение пропускало слабые косинусные совпадения, включая нерелевантные результаты на запрос приветствия. При миграции старый дефолт 0.35 заменяется на 0.65, а иное сохранённое значение пользователя переносится. В обеих оболочках текст источника скрыт до открытия `Original Text`; фрагмент не дублируется над раскрывающимся блоком.

## Исправление пустого ответа Gemma и номеров формул — 2026-10-28

При включённом thinking Gemma 4 e2b раньше могла потратить `num_predict=768` на reasoning и вернуть пустой `message.content`; поэтому генерация вызывает Ollama с `think:false`. Отдельно на запросе «таблица интегралов» обе попытки упирались ровно в лимит вывода: `eval_count=768`, `done_reason=length`, без цитат. Контекстного переполнения не было: Ollama сообщила окно модели 131072, запрос ограничен 8192, фактический prompt содержал 1080–1197 токенов. `num_predict` повышен до 2048; после этого реальный запрос завершился на 955 токенах (`done_reason=stop`) и прошёл citation validation с первой попытки. Ответ Ollama с `done_reason=length` теперь отклоняется как обрезанный, а не проходит проверку частичного текста. Opt-in тест на синтетической таблице из 19 формул также прошёл на `gemma4:e2b`. Контекст помечает источники как `[SOURCE n]`, валидатор нормализует их в `[n]`; OCR-метки `\textcircled{n}` исключаются только из prompt.
