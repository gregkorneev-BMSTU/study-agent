# Решения и нерешённые вопросы

## Зафиксированные требования

- Python — основа локального ядра; пользовательские документы и генерация ответов остаются локальными по умолчанию.
- Целевой продукт — настольное приложение для Windows и macOS, распространяемое через GitHub без зависимости от путей и настроек автора.
- Пользователь сам выбирает корневые директории. Первичная индексация начинается автоматически после добавления выбранной папки; приложение не сканирует неизвестные каталоги.
- Chandra OCR — целевой OCR для сканов, рукописей и изображений. Используется локальный режим; качество, совместимость, производительность и лицензия весов должны быть проверены до дистрибуции.
- Локальная Qwen используется для RAG и смыслового анализа; локальные эмбеддинги готовят поисковые представления. Конкретные модели/рантаймы не выбраны.
- Ответы основываются на найденных фрагментах и должны иметь ссылки на исходные материалы. При недостатке данных система сообщает об этом.
- Индексы, кэш, пользовательские корни и модели хранятся локально вне репозитория. В исходном коде/публикуемых конфигурациях нет персональных абсолютных путей или документов.
- IU5Hub — отдельный внешний источник через самостоятельный адаптер; сам проект iu5hub не изменять, не подключать как подмодуль и не импортировать его исходники.
- Вся разработка ведётся в `main`. Не создавать `beta` без нового указания пользователя; не переписывать историю и не force-push.
- Полная цель реализуется этапами. Модели и полноценный RAG не требуются для стандартного CI.

## Нерешённые технические решения

1. UI-фреймворк и способ упаковки Windows/macOS.
2. Форматы документов, поддерживаемые в первом выпуске, и библиотеки извлечения PDF/DOCX.
3. Подтверждённая локальная совместимость/скорость Chandra на Apple Silicon и Windows, особенно для русского почерка; ограничения на распространение весов.
4. Локальный runtime, версия и квантование Qwen; качество и память на обоих целевых устройствах.
5. Модель эмбеддингов и качество для русских запросов.
6. Хранилище индекса и пользовательских данных, миграции/резервное копирование и политика очистки.
7. Смешивание лексического и векторного поиска, пороги достаточности найденного контекста.
8. Проверенный API/способ загрузки выбранных материалов IU5Hub, лимиты и правила использования.
9. Границы и подтверждения действий для MCP-инструментов.
10. Минимальные системные требования и политика первоначальной загрузки моделей для дистрибутива.

Каждое решение закреплять после тестового прототипа или измерений, с датой и кратким обоснованием.
