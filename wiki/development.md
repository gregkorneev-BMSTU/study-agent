# Разработка и Git

## Codex

Главный агент работает как Orchestrator: изучает Wiki, назначает независимые задачи, интегрирует изменения, запускает проверки и обновляет документацию. Роли и правила описаны в корневом `AGENTS.md`. Субагенты нужны только для независимых работ; максимум три одновременно. Они не меняют одни файлы без координации и не коммитят/push. Используйте возможности субагентов, реально предоставленные сессией; `AGENTS.md` сам по себе не запускает агентов.

В этой сессии были доступны инструменты делегирования, и два агента провели независимые read-only аудиты стека и IU5Hub. Codex инструктируется через `AGENTS.md`; постоянная регистрация ролей как фоновых агентов здесь не настраивалась.

## Git

- `main` — стабильное состояние; `beta` — обычная разработка.
- Для пустого удалённого репозитория можно создать начальное документальное состояние в `main`, затем продолжить в `beta`.
- Коммитите логически законченные, проверенные изменения с соответствующей Wiki.
- Перед коммитом просмотрите `git diff`, `git status` и точный список staging-файлов. Не включайте `.env`, пользовательские документы, модели, базы/индексы и кэши.
- Публикуйте только в `beta`, если `origin` и аутентификация рабочие. Проверяйте push по результату Git. Не force push.
- Перенос `beta` в `main` и релизы требуют отдельного разрешения.
- В исходном `iu5hub` ничего не менять.
