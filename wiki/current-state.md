## OCR визуального содержимого — 2026-10-28

В [Beta 6.1](https://github.com/gregkorneev-BMSTU/study-agent/releases/tag/v1.0.0-beta.6.1) зафиксировано общее правило: запускать Chandra для визуального содержимого, даже если рядом есть печатный текст, поскольку на нём могут быть рукописные пометки. Оно применяется к каждой странице PDF, встроенным изображениям DOCX и локальным изображениям, указанным в Markdown (они индексируются как отдельные файлы). Печатный текст сохраняется вместе с результатом OCR. Обновлённые версии извлечения PDF/DOCX и ключ PDF-кэша вызывают повторную обработку после обновления приложения и действия «Проверить изменения». ## Проверка SA-01

После повторного ревью PySide6-клиент индексирует источники в рабочем потоке при добавлении и удаляет их записи из SQLite при удалении из библиотеки. Поиск и операции с библиотекой выполняются последовательно. macOS-клиент приводит пути выбранных папок и символических ссылок к тому же каноническому пути, который возвращает Python backend. CI проверяет повтор неудачных операций macOS-модели с подменным backend и собирает приложение целиком. Локальные результаты и границы проверки приведены в [тестировании](testing.md).

Запросы индексации macOS-клиента проходят через одну последовательную очередь; занятая другим процессом блокировка вызывает повтор запроса после задержки. Пустой результат поиска во время первичной обработки сопровождается `indexing=true`, чтобы UI не сообщал об окончательном отсутствии совпадений. Ошибка `stat()` отдельного файла не останавливает обход и не удаляет его старые фрагменты. При возвращении FTS5 после fallback индекс восстанавливается из основной таблицы и триггеры включаются снова. Проверки и ограничения зафиксированы в [тестировании](testing.md). Это ещё не выпущенная версия приложения.

После ревью PR #11 macOS-клиент сохраняет путь каждой выбранной папки вместе с bookmark. Поиск и список источников используют этот путь без разрешения bookmark, поэтому ошибка доступа к одному отключённому источнику не блокирует поиск по сохранённому индексу и остальным источникам. Старые записи получают путь при успешном разрешении bookmark; случай, когда старая закладка уже не разрешается, требует повторного подключения папки.

Ошибки индексации и удаления источника теперь оставляют операцию доступной для повтора через кнопку в Библиотеке; при возвращении приложения на передний план повтор запускается автоматически. Ожидающие удаления пути сохраняются между запусками до успешного удаления из SQLite, чтобы ошибка backend не оставила скрытый индекс удалённого источника навсегда.

Локальный Qt-сбой полного pytest объяснён скрытым флагом у платформенных плагинов PySide6 в `.venv`. При использовании копий плагинов без этого флага полный набор прошёл: 72 теста. [CI для PR #11](https://github.com/gregkorneev-BMSTU/study-agent/actions/runs/40207795289) прошёл на Python 3.12, 3.13 и macOS. Подробности и оставшийся ручной сценарий с физическим отключением диска указаны в [тестировании](testing.md).

## SA-04 — нативная индексация и источники ответа

В ветке `feature/sa-04-swiftui-indexing` библиотека macOS показывает очередь, фазу и реальные счётчики JSON Lines progress, статистику SQLite и время последней полной индексации. Действие «Проверить изменения» использует `sync_source`; обработку можно отменить отменой Swift task, которая завершает выделенный helper. Поиск сохраняет метаданные фрагментов SA-01/SA-02, а карточки и раздел «Использованные источники» строятся из исходных SearchHit. Поле `index_status.last_indexed_at` читает уже существующую `sources.indexed_at`, схема БД не менялась.

Это состояние разработки на ветке, не опубликованная Beta 4. Встроенного PDF page viewer нет: интерфейс показывает реальную страницу, но открывает PDF в приложении по умолчанию и не обещает переход к странице. Ручные сценарии на запущенном приложении, VoiceOver и фактическое открытие источников ещё требуют QA. Подробности реализации и границы проверки: [нативная индексация macOS](macos-indexing-ui.md).

В финальном ревью `index_status.issues` начал возвращать сохранённые ошибки/предупреждения SQLite, а UI после перезапуска восстанавливает список. Backend errors сохраняют технический code отдельно от локализованного пользовательского описания; поздний progress после `.cancelling`/`.cancelled` игнорируется. Сквозной production-backend прогон TXT/PDF/DOCX подтвердил первичную индексацию, обновление и удаление. Светлая/тёмная темы просмотрены на изолированном build; малое окно и живые cancel/error действия UI, VoiceOver и macOS 14 остаются непроверенными. Результаты приведены в [тестировании](testing.md) и [QA отчёте](../artifacts/sa-04-swiftui-qa/README.md).
## Результаты поиска SA-03 — 2026-10-28

Локальная ветка `codex/sa03-context-threshold` группирует выдачу по файлу: одна карточка на документ хранит все совпавшие фрагменты. Совпавшие чанки вместе с соседними чанками того же файла передаются в контекст локальной модели; в интерфейсе соседний контекст не маскируется под совпадение. Порог косинусного сходства настраивается в параметрах поиска (по умолчанию 0.35); гибридный режим сохраняет точное лексическое совпадение и отсекает прочие ключевые совпадения, которые не прошли порог. Изменения ещё не проверены полным набором и не коммичены.
## Релевантность и свёрнутые источники SA-03 — 2026-10-28

В рабочей ветке `codex/sa03-search-noise-ui` повышен дефолт порога сходства до 0.65 с переносом изменённых пользовательских значений. В карточках текст чанков скрыт в `Original Text` по умолчанию и не дублируется. Полный тест weak-match покрывает вектор с cosine 0.5: он отсекается новым дефолтом и проходит при явно сниженном до 0.35 пороге. Изменение проверяется до локального коммита.
## Ошибка ответа на «таблица интегралов» — 2026-10-28

В локальной ветке `feature/sa-03-rag` собраны коммиты предыдущих `codex/sa03-*` веток; промежуточные ссылки удалены, `main` не менялся. Gemma 4 e2b обрезала ответ таблицы интегралов на старом лимите `num_predict=768`, хотя вход занимал около 1100 токенов при `num_ctx=8192`. Лимит увеличен до 2048, правила ссылок уточнены для каждого пункта и формулы, а усечённые ответы больше не проходят как завершённые. Реальный запрос прошёл с первой попытки (955 выходных токенов, `done_reason=stop`); opt-in тест на синтетической таблице из 19 формул прошёл.

В поисковой выдаче порядок совпавших чанков одного файла теперь берётся из `chunks.ordinal`, а не из порядка релевантности. На macOS карточка использованного источника не дублируется в блоке ответа: номер цитаты показывается на карточке файла в результатах.

Повторная проверка обнаружила, что retrieval-путь терял `ordinal`, когда преобразовывал строки SQLite в `SearchHit`; сортировка поэтому получала только порядок ранжирования. `_hit` теперь переносит `c.ordinal` в модель результата, а интеграционный regression test подаёт чанки намеренно в обратном порядке и проверяет исходную последовательность в выдаче.

Для всех ответов общий prompt требует минимально необходимый текст и только ту Markdown-структуру, которая облегчает чтение: без приветствий, вступлений, самоссылок на материалы, повторов и незапрошенных пояснений. При точном воспроизведении таблиц, списков и формул сохраняются Markdown и порядок источника. Сквозные проверки на Qwen/Gemma покрывают определения, несколько источников, отказы и формулы.
