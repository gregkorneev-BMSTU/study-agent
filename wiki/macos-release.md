# macOS Beta: установка и выпуск

## Состав и установка

Нативное приложение собирается Xcode для macOS 14+ на Apple Silicon. SwiftUI-интерфейс использует встроенный Python helper (`Contents/Resources/Backend`) через JSON Lines. Конечному пользователю не нужен отдельный Python или PySide6. Поддержка Intel и Universal Binary для этого образа не заявлена.

DMG содержит `Study Agent.app` и ссылку `Applications` на `/Applications`. Пользователь переносит приложение обычным способом Finder. Образ не запускает скрипты при монтировании. Окно Finder использует системный фон и поэтому адаптируется к светлой и тёмной теме; композиция 660 × 380 pt, приложение слева, Applications справа. Статический фон ради стрелки/подписи не используется.

В `.app/Contents/Resources/Legal` сборка копирует MIT License проекта, `THIRD_PARTY_NOTICES.md`, лицензию Python и найденные лицензионные файлы Python-пакетов; `PYTHON_BUILD_ENVIRONMENT.csv` фиксирует версии и заявленные лицензии среды сборки, включая пакеты, которые могут быть только инструментами сборки. Проверяйте фактически упакованный helper и юридические материалы для каждого релиза. В Beta 3 диагностика упакованного arm64 helper подтвердила `chandra` runtime. Веса модели не включаются. OCR inference с весами ещё не проверен. PySide6/Qt-дистрибуция Windows и происхождение части графики требуют отдельной проверки.

На чистом первом запуске SwiftUI сначала показывает три страницы знакомства, затем открывает существующий пятишаговый мастер: короткий экран перед настройкой, проверка Mac, компоненты, локальная модель, завершение. Проверяются версия macOS, архитектура, RAM, свободное место, встроенный backend/PDF/OCR runtime, доступность сайта Ollama, локальный API Ollama и список установленных моделей. Результат проверки показывается в том же модальном окне; запуск установки и загрузка модели требуют действия пользователя. Знакомство и техническая настройка сохраняются раздельно (`onboarding.introduction.seen.v1` и `setup.completed.v1`). У знакомых Beta 1/Beta 2 не появляется новое приветствие после обновления. Повторный вход в диагностику доступен через **Настройки → Компоненты и диагностика**, а знакомство можно запустить из меню **Справка**. Приложение из смонтированного DMG предлагает сначала перенести в «Программы».

При найденной, но остановленной Ollama мастер предлагает открыть установленное приложение. При отсутствии Ollama он открывает только [официальную страницу загрузки](https://ollama.com/download); скачивание и установка самого дистрибутива остаются системным графическим процессом Ollama. Study Agent не проверяет подпись стороннего загруженного пакета. Для работающей Ollama мастер предлагает Qwen 3.5 4B через локальный `POST /api/pull`: данные модели идут в Ollama, а интерфейс показывает переданные API статус и `completed/total`, если они есть. Доступны отмена и повторная попытка. Уже установленная выбранная модель определяется через `GET /api/tags`; автоматической повторной загрузки нет. Оценка 3,3–4 ГБ взята из [каталога Ollama](https://ollama.com/library/qwen3.5/tags), это размер файла, а не гарантированный объём RAM.

Chandra OCR runtime включён в Beta 3; проверка `diagnose_backend` вернула `ocr_runtime_available=true`. Веса отдельно скачиваются пользователем с явного действия в мастере настройки. Поиск сам не начинает сетевую загрузку весов. Без весов OCR недоступен; inference и качество OCR не проверялись. Текстовые файлы и цифровой слой PDF доступны без OCR. Условия исходного кода Chandra и весов модели различаются; подробности приведены в [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).

После Beta 3 обнаружена ошибка упаковки OCR: PyInstaller не включал нативные файлы `torchvision/*.so` и `torchvision/.dylibs`. На сканированных PDF это приводило к аварийному завершению helper и сообщению «Локальный backend вернул некорректный ответ». Скрипт `scripts/build_macos_native_app.sh` теперь добавляет эти файлы, если `torchvision` установлен в окружении сборки. Проверять выпуск следует на упакованном `.app`, а не только в Python-окружении; наличие `ocr_runtime_available=true` само по себе не подтверждает работу inference.

## Сборка разработчика

На Mac с Xcode, Python 3.12 и установленными `.[packaging,ocr]`:

```sh
./scripts/build_macos_native_app.sh
./scripts/build_macos_dmg.sh --mode development --suffix beta.5
```

Скрипт DMG может использовать готовый `.app` через `--app`, чтобы не повторять сборку. Версию и номер сборки он читает из `Info.plist`, которые заданы `MARKETING_VERSION` и `CURRENT_PROJECT_VERSION` Xcode. Development-режим подписан ad-hoc и подходит для локальной проверки; он не является нотариализованным дистрибутивом.

Для публичной дистрибуции нужны действующий сертификат **Developer ID Application** и профиль `notarytool` в Keychain. Укажите `DEVELOPER_ID_APPLICATION` и `NOTARY_PROFILE`, затем используйте `--mode distribution`. Скрипт переподписывает вложенные Mach-O и bundle с Hardened Runtime, проверяет подпись, отправляет приложение и DMG на нотариализацию Apple, прикрепляет билеты и проверяет их. Пароли и сертификаты в репозитории не хранятся. Без этих реквизитов режим distribution завершается ошибкой; ad-hoc образ нельзя называть обычным подписанным релизом.

Перед выпуском нужно смонтировать DMG, проверить два корневых элемента и ссылку `/Applications`, позиции иконок в Finder, обе системные темы, запуск приложения из скопированной папки, подпись/Gatekeeper и SHA-256. На другом Mac повторить сценарий чистой установки. Графическое оформление Finder может зависеть от версии macOS и пользовательских настроек; не следует выдавать один скриншот за проверку всех конфигураций.

## Публикация

Опубликованный выпуск: **Study Agent v1 Beta 4**, тег `v1.0.0-beta.4`, Xcode `CURRENT_PROJECT_VERSION = 4`, файл `StudyAgent-v1.0.0-beta.4-macos-arm64.dmg`. Release assets и двуязычные release notes находятся на [странице GitHub Release](https://github.com/gregkorneev-BMSTU/study-agent/releases/tag/v1.0.0-beta.4) и в [`wiki/releases/v1.0.0-beta.4.md`](releases/v1.0.0-beta.4.md). Перед каждым новым GitHub Release выполнить Python/Xcode проверки, убедиться, что DMG соответствует коммиту и тегу, проверить состав образа и подпись извлечённого приложения, вычислить SHA-256 и перечислить функции/ограничения на русском и английском. Для ad-hoc сборки использовать пометку **pre-release / test build** с явным предупреждением об отсутствии Developer ID и нотариализации. При появлении Developer ID и успешной нотариализации выпускать новый артефакт с новым номером сборки/тегом, не подменяя старые файлы.

Для Beta 3 `hdiutil verify` подтвердил целостность DMG. Строгая проверка непосредственно на смонтированном HFS+ томе показывает FinderInfo extended attributes на вложенных файлах лицензий; после копирования `.app` в обычный каталог `codesign --verify --deep --strict` проходит. Зафиксируйте оба результата и не называйте сборку нотариализованной.

В обычном CI реальные модели Chandra/Qwen не скачиваются. Unit-тесты проверяют Python bridge синтетически; визуальные и системные шаги на macOS проверяются отдельно. Текущие результаты и ограничения записываются в [тестировании](testing.md) и [текущем состоянии](current-state.md).
