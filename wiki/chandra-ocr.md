# Локальный OCR Chandra и извлечение данных

## Реализация

`LocalFolderSource` поддерживает широкий набор форматов учебных материалов: цифровые и сканированные документы `.pdf`, текстовые файлы `.txt`/`.md`, структуры документов `.docx`, а также форматы изображений `.png`, `.jpg`, `.jpeg`, `.webp`, `.tif`, `.tiff` и `.bmp`.

Пайплайн извлечения контента построен следующим образом:
1. **Текстовые и цифровые файлы:** Для файлов Word (`.docx`) применяется легковесный локальный парсер на базе `python-docx`, извлекающий абзацы с привязкой к иерархии заголовков (`heading`) и плоские таблицы. Для PDF базовой зависимостью выступает `pypdfium2`, который извлекает цифровой текстовый слой.
2. **Локальный OCR:** Общее правило — распознавать визуальное содержимое независимо от того, есть ли рядом печатный текст: в нём могут быть рукописные пометки. Chandra обрабатывает каждую страницу PDF, каждое встроенное изображение в основном содержимом DOCX (включая таблицы) и каждый отдельный файл изображения. Печатный текст при этом сохраняется. Локальные изображения, указанные в Markdown, индексируются и распознаются как отдельные файлы внутри выбранной папки. Текстовые `.txt` и `.md` без изображений сами по себе пикселей для OCR не содержат. Внешние URL и файлы за пределами выбранной папки не загружаются.
3. **Изоляция ошибок:** Обработка ошибок внутри многостраничных документов изолирована. Сбой Chandra или повреждение конкретной страницы не блокирует индексацию и чтение остальных страниц или документов; диагностическое сообщение сохраняется в поле метаданных `warnings` конкретного блока.

### Контракт данных и кэширование

Извлечённый контент больше не транслируется в виде сырой строки с техническими заголовками. Функция `extract_document` возвращает строго типизированный список блоков `list[ExtractedBlock]`, содержащий:
- Чистый текст фрагмента (без примеси управляющих Markdown-тегов страниц).
- Позиционирование: явный `page_number` для PDF (строго `None` для DOCX) и контекстный `heading` для DOCX.
- Тип извлечения (`digital` или `ocr`) и массив неблокирующих предупреждений.

Распознанный результат кэшируется в системном каталоге пользовательского кэша вне папки источника и репозитория. В целях безопасной миграции и предотвращения конфликтов в командной разработке формат кэша переведён на изолированное расширение `.json` (ключ строится по SHA-256 хэшу исходного файла). Старые текстовые `.md` файлы кэша на `main` ветке игнорируются кодом и не повреждаются.

Для режима распознавания каждой страницы ключ PDF-кэша содержит версию `pdf-3`, а версии обработки PDF и DOCX в индексе повышены отдельно от остальных форматов. При следующем действии «Проверить изменения» ранее добавленные PDF и DOCX извлекаются заново, даже если размер и время изменения файлов прежние; старый JSON-кэш PDF не используется. Установленные веса Chandra и оригиналы документов не изменяются. Обработка PDF с большим числом страниц теперь требует больше времени и ресурсов; сбой OCR сохраняет доступный цифровой текст и показывает предупреждение.

Установить OCR-зависимости в окружение разработки:

```sh
python -m pip install '.[ocr]'
```

В окружении разработки поиск по выбранной папке с изображениями или сканированным PDF запускает локальный Hugging Face режим Chandra. В упакованном macOS `.app` автоматическая загрузка при поиске отключена. Пользователь может явно установить Chandra из мастера «Компоненты и диагностика»: приложение скачивает snapshot модели `datalab-to/chandra-ocr-2` (10,6 ГБ) с Hugging Face и показывает прогресс/отмену. Файлы сохраняются в `~/Library/Application Support/Study Agent/Models/Chandra`; повторная загрузка продолжает частичный snapshot. Тег модели закреплён на revision `af93b47dba1b47b6640c86ccf487ed2260ab9a09`. Пользовательские документы в загрузчик не передаются.

Цифровые PDF и документы DOCX доступны и без OCR-группы. Если OCR runtime отсутствует, приложение просит переустановить сборку; если runtime есть, но модель не установлена, настройки показывают кнопку установки. Диагностика проверяет marker, `config.json` и веса локально без запуска модели и без сети. Отмена загрузки останавливает helper; повторный запуск Hugging Face продолжает незаконченные файлы. OCR при распознавании остаётся offline-only в упакованном приложении. Быстрые тесты подменяют PDF renderer/OCR и загрузчик; сеть и модель не запускаются.

## Лицензии и границы

- Код Chandra опубликован под Apache 2.0; лицензия Study Agent MIT его не заменяет.
- Для весов закреплённой модели есть отдельная **Modified OpenRAIL-M**. Приложение не включает и не распространяет веса: каждый пользователь явно скачивает их на свой компьютер. Перед установкой из приложения доступна ссылка на лицензию закреплённой ревизии. Соблюдать нужно все условия самой лицензии.
- В тексте лицензии есть ограничения для организаций с выручкой/финансированием выше $2 млн (кроме личного использования или исследований), для конкурирующих с Datalab сервисов, требования атрибуции и Share-a-Like-условие для Output. README Chandra отдельно требует лицензию для коммерческого self-hosting. Эти условия могут касаться результатов OCR; Study Agent не определяет их соотношение с правами на документы пользователя. Перед распространением OCR-результатов или любым сомнительным сценарием нужно проверить права на исходный документ и обратиться к Datalab или юристу.
- В Beta 3 `diagnose_backend` внутри извлечённого macOS приложения вернул `ocr_runtime_available=true`; Chandra runtime включён в helper. Модельные веса не включены, статус диагностики — `missing`. Inference в упакованной Beta 3 не проверялся.
- Не подключать облачный Datalab API как fallback. Документы передаются только локальному процессу Chandra.

Исходники и тексты лицензий: [Chandra](https://github.com/datalab-to/chandra), [лицензия кода Chandra](https://github.com/datalab-to/chandra/blob/master/LICENSE), [закреплённая модель и её LICENSE](https://huggingface.co/datalab-to/chandra-ocr-2/tree/af93b47dba1b47b6640c86ccf487ed2260ab9a09), [сводка лицензий Study Agent](../THIRD_PARTY_NOTICES.md).

## Не проверено

В PR #10 поиск передаёт предупреждения OCR страниц в поле `search.result.warnings` с относительным ID и номером страницы. Текст ошибки OCR не покидает слой извлечения. Кэш JSON используется для PDF и отдельных изображений; `.txt` и `.md` читаются без него, локальные картинки из Markdown обрабатываются как самостоятельные изображения. Для DOCX обходятся верхнеуровневые абзацы и таблицы в порядке документа, контекст заголовков хранится как breadcrumb. Вложенные таблицы, колонтитулы, сноски и текстовые поля не извлекаются.

Исторические проверки Beta 3 выявили, что прежнее правило пропускало OCR, если в PDF был читаемый печатный текст. В Beta 6.1 это исправлено: проверка упакованного backend подтвердила OCR для изображения страницы, PDF с текстовым слоем и DOCX с печатным абзацем и встроенным изображением; детали и ограничения приведены в [заметках Beta 6.1](releases/v1.0.0-beta.6.1.md). Систематические измерения точности на русской печати, рукописи, формулах и сложных таблицах, а также сравнительные измерения времени и памяти на Apple Silicon и Windows ещё не проводились.
