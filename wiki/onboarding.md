# Первый запуск macOS

## Поток

Первый запуск нового пользователя открывает один sheet с Welcome Experience из трёх страниц. Кнопки «Продолжить»/Continue и «Назад»/Back перемещают между страницами; пропуск и последнее действие переводят к уже существующему `SetupWizard` в том же sheet. После знакомства мастер начинает свою проверку компьютера, затем предлагает компоненты и локальную модель. Установка Ollama, Qwen и Chandra не запускается без отдельного действия пользователя.

Знакомство объясняет назначение приложения, работу библиотеки и локальную обработку. Оно не обращается к backend, не загружает модели и не открывает пользовательские папки. Обычные обновления источников и моделей откладываются до окончания/закрытия этого первого sheet.

## Сохранение состояния и миграция

- `onboarding.introduction.seen.v1` хранит только факт завершённого или пропущенного знакомства.
- `setup.completed.v1` остаётся признаком завершения технического мастера.
- На Beta 1/Beta 2, где `setup.completed.v1` уже установлен, новый Welcome Experience не показывается; состояние знакомства помечается пройденным для совместимости.
- Если пользователь закрыл приложение до последней страницы, знакомство не считается пройденным и будет предложено снова.
- Закрытие технического мастера не выставляет `setup.completed.v1`; проверку можно повторить при следующем запуске.
- После настройки знакомство можно открыть повторно из **Справка → Пройти знакомство ещё раз**.

`FirstRunPresentation` управляет `.welcome` и `.setup` как стадиями одной модальной панели. Так welcome и технический мастер не представляются одновременно. Отдельная системная Settings scene не открывается поверх знакомства; существующая настройка и диагностика запускаются сразу следующим шагом после третьей страницы.

## Двуязычный интерфейс меню

Тексты Welcome Experience используют существующий `L10n`. Выбранный язык сохраняется в `general/language`. Изменение заголовков стандартных верхних меню AppKit (`File`, `Edit`, `View`, `Window`, `Help`) выполняется после создания главного NSMenu; название приложения Study Agent остаётся брендом и не переводится. SwiftUI-команды внутри этих меню продолжают использовать существующий список локализаций.

## Ограничения QA

Реальный UI проверяется на macOS 27; deployment target остаётся macOS 14. Accessibility tree подтверждает доступные подписи страниц, кнопки и индикатора `Шаг N из 3`/`Step N of 3`. Физический аудит VoiceOver, клавиатурной навигации на всех шагах и Reduce Motion должен выполняться отдельно от визуального smoke test. Скриншоты реального Release UI и ограничения текущей проверки лежат в [отчёте QA onboarding](../artifacts/macos-onboarding-qa/README.md).
