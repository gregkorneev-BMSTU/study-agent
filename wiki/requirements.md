# Требования

## Назначение и целевые платформы

Приложение — кроссплатформенный настольный агент для локального поиска и анализа учебных материалов. Целевые платформы: Windows (устанавливаемое приложение `.exe`) и macOS (`.app`, например в `.dmg`). Код распространяется через GitHub и должен запускаться на компьютерах других пользователей без путей, настроек, документов или моделей автора.

Пользователь выбирает одну или несколько директорий с лекциями, учебниками, методическими указаниями, лабораторными работами, сканами и конспектами. Из выбранных материалов формируется персональная база знаний. Подключённые локальные материалы, индекс и ответы не отправляются в облачные модели или внешние поисковые системы.

После первоначальной установки и загрузки нужных моделей приложение должно работать локально и офлайн для уже подключённых материалов. Сетевой доступ может использоваться для установки обновлений/моделей и отдельно выбранного источника IU5Hub; это не разрешает отправлять туда документы пользователя.

## Основные разделы приложения

### Поиск

- Принимать обычные поисковые фразы и вопросы на естественном языке.
- Определять, достаточно ли поиска по названию/метаданным/тексту, либо нужен ответ RAG.
- Поддерживать поиск по одному и нескольким документам, выдержки и обобщение.
- Позже поддержать ограниченные действия агента через инструменты MCP.
- Показывать ответ, найденные фрагменты и проверяемые ссылки на источники.

### Библиотека

- Позволять выбрать несколько директорий через системный диалог.
- После явного добавления директории автоматически начинать её первичную индексацию.
- Показывать найденные файлы, прогресс, число документов/фрагментов и ошибки.
- Позволять повторно индексировать изменения и удалить источник из базы знаний.
- Сохранять библиотеку и индекс между запусками.
- Поддерживать IU5Hub как отдельный пользовательски выбираемый источник.

## Подготовка документов

1. **Обнаружение.** Рекурсивно находить поддерживаемые файлы, фиксировать формат, размер, дату изменения, путь и состояние обработки. Не обрабатывать неизменённый документ повторно без необходимости.
2. **Извлечение.** Для файлов с текстовым слоем извлекать текст напрямую. Для сканов и изображений использовать OCR. Исходники не изменять.
3. **OCR.** Chandra OCR — целевой компонент для сканированных страниц, изображений и рукописей. OCR запускать только там, где извлечения существующего текста недостаточно. Локальный режим обязателен для пользовательских документов; удалённый API не использовать по умолчанию.
4. **Анализ.** Локальная Qwen может определять темы, термины, разделы и краткое описание. Не прогонять каждый документ через LLM, если метаданные можно получить программно.
5. **Индексация.** Разбивать текст на фрагменты, строить локальные эмбеддинги и сохранять фрагменты с метаданными в постоянное локальное хранилище.
6. **Завершение.** Сообщать о готовности, количестве документов и фрагментов, а также о сбоях с возможностью повторить обработку.

Для каждого результата сохранять идентификатор источника, относительный путь внутри выбранной директории, заголовок/предмет (если известны), страницу и связь с исходным фрагментом. Результаты OCR и индекс хранить в пользовательских данных приложения, отдельно от оригиналов и Git-репозитория.

## Поиск и ответы

- Использовать локальный лексический и семантический поиск по индексу.
- Для ответа передавать локальной Qwen только найденный контекст.
- Позволять выбрать и менять установленную локальную языковую модель в настройках; не зашивать конкретное имя/размер модели в логику приложения. Целевой профиль по умолчанию — лёгкая совместимая модель, а дополнительные модели используются по возможностям компьютера.
- Не использовать знания предобученной модели как самостоятельное подтверждение фактов об учебных материалах.
- Если найденного контекста недостаточно, прямо сообщать об этом, например: «В подключённых учебных материалах не найдено информации, достаточной для ответа на данный вопрос».
- Ссылки на документы, страницы и фрагменты строить из индекса, а не просить модель их выдумывать.

## Происхождение и открытие источников

Ответы должны включать название документа, предмет/раздел, страницу и соответствующий фрагмент, если данные доступны. Источник должен открывать оригинал, по возможности на нужной странице. Приложение хранит выбранные пользователем корневые пути только в локальном состоянии; в общем коде и публикуемых конфигурациях используются относительные пути и ID источников.

## Распространение и конфиденциальность

- GitHub-репозиторий не содержит персональные абсолютные пути, пользовательские документы, индексы, базы, кэш, `.env` и файлы моделей.
- Пути к исходникам задаются пользователем во время работы. Переменные окружения и пользовательские настройки не должны быть обязательны для стандартного запуска.
- Тесты используют синтетические или явно разрешённые обезличенные фикстуры.
- Установка, хранение данных, пути, файловые диалоги и упаковка проверяются на Windows и macOS.
- Лицензии Chandra и весов, Qwen, эмбеддингов и других распространяемых компонентов проверяются отдельно от лицензии исходного кода до публикации дистрибутива.
- Никаких незаметных облачных fallback-моделей и передачи документов внешним сервисам.

## Этапность и критерий первой версии

Полная цель включает автоматическую обработку документов, OCR, локальные эмбеддинги, RAG и интерфейс. Реализовывать её следует по проверяемым этапам; модели и полный RAG не загружать в базовый CI.

Первый сквозной результат: на чистой установке пользователь выбирает папку, приложение индексирует несколько поддерживаемых документов, сохраняет индекс вне репозитория, находит текстовый фрагмент и показывает точный исходный документ/страницу. Затем этот поток расширяется OCR, семантическим поиском, Qwen-ответами, IU5Hub и MCP-действиями.

Пилотный корпус для проверки первой производительности — 10–100 документов; это не ограничение целевой библиотеки. Поддерживаемые форматы и минимальные системные требования фиксировать после измерений на Windows и macOS.
