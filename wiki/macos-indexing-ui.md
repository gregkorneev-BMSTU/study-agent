# Нативная индексация и поиск macOS

## Сценарий пользователя

При добавлении папки клиент сохраняет её security-scoped bookmark и ставит синхронизацию в существующую последовательную очередь `StudyAgentModel`. Строка библиотеки показывает количество документов и фрагментов из `index_status`, состояние источника, реальные события progress и итоговые предупреждения. «Проверить изменения» запускает обычную инкрементальную `sync_source`; «Остановить обработку» отменяет активный helper. Действие удаления убирает источник из библиотеки и после текущей операции очищает только его записи индекса.

## Источник состояния

- Очередь SwiftUI содержит ожидающие и текущую операцию. Она не хранится в SQLite.
- `sync_source`/`index_source` присылают JSON Lines `progress` с совпадающим `request_id`, фазой и счётчиками `current`, `total`, `indexed`, `partial`, `skipped`, `failed`. Определённый `ProgressView` используется только при `total > 0`; в противном случае UI не вычисляет процент.
- `index_status` читает SQLite: `documents`, `ready`, `partial`, `failed`, `chunks`, `last_indexed_at`. Последнее поле читается из уже существующего `sources.indexed_at`; база не мигрирует.
- `list_sources.available` отражает доступность исходной папки. Отключённый источник может оставаться в списке и сохранять фрагменты поиска.

Статистика загружается после обновления библиотеки и завершения операции, не во время каждого SwiftUI render pass. SwiftUI не открывает SQLite напрямую.

## Очередь, отмена и повтор

Добавления и повторная синхронизация используют одну последовательную очередь. Запросы `index_busy` возвращаются в очередь и повторяются с задержкой. Завершённые документы сохраняются транзакциями backend, а отменённая синхронизация не устанавливает время последнего полного обхода.

В JSON Lines нет отдельной команды отмены. Отмена Swift task задействует `withTaskCancellationHandler` существующего клиента и завершает выделенный helper процесс. Это может прервать текущий OCR документ; SQLite откатывает незавершённую транзакцию, а уже записанные фрагменты остаются доступны. Backend не гарантирует финальный envelope после завершения процесса, поэтому интерфейс отмечает локальную операцию отменённой и не выводит её как успешную.

## Ошибки и недоступные источники

Коды документов (`document_extraction_failed`, `ocr_failed`, `document_disappeared`, `permission_denied`, `document_stat_failed`) переводятся в понятные подсказки. Ошибки одной операции не подменяют сохранённую статистику и не скрывают уже найденные фрагменты. После успешного повторного прохода список старых ошибок заменяется свежим отчётом.

Если папка недоступна, `list_sources` оставляет её в библиотеке с сохранённым количеством документов, а поиск читает прежние фрагменты по ID источника. Если конкретный оригинал пропал или оказался вне корня, карточка и её текст остаются, открытие прекращается с сообщением; повторное подключение доступно из действий папки.

## Результаты и источники ответа

`SearchHit` сохраняет `page_number`, `heading`, `marker`, `extraction_type`, `chunk_id`. SwiftUI ID включает корень, относительный путь и `chunk_id`; если backend его не прислал, декодированный результат получает собственный UUID. PDF page number показывается только из backend; для DOCX показывается реальный `heading`, выдуманные страницы не добавляются. Открытие проверяет канонический путь оригинала внутри выбранной папки и использует системное приложение.

Текущий backend отправляет Ollama не более пяти найденных фрагментов. Клиент отправляет эти первые пять и сохраняет тот же список в `answerSources`; секция «Использованные источники» показывается только после непустого ответа. Номера ссылок соответствуют фактическому порядку hits запроса `answer`, метаданные взяты из SearchHit, а не из текста модели. Это подтверждает происхождение переданного контекста, но не проверяет автоматически каждое утверждение ответа.

PDF страница отображается в карточке, но встроенного PDFKit viewer и надёжного перехода к странице пока нет. `NSWorkspace.open` открывает файл в приложении по умолчанию; конкретная страница в нём не гарантируется. DOCX открывается системным приложением без перехода к заголовку или маркеру.

## Совместимость и ограничения

Реализация переиспользует Python services SA-01/SA-02 и существующий JSON Lines protocol. Не добавляются отдельная очередь, база, embedding или RAG слой; будущий SA-03 может передавать свой список retrieval chunks в UI. Новое `last_indexed_at` является совместимым полем ответа `index_status`.

На момент обновления страницы Xcode Debug/Release сборки и unit harness прошли. В отдельной копии `.app` с синтетическим bridge вручную проверены пустая библиотека, строка источника и карточки поиска с двумя источниками ответа. Это не заменяет сквозной прогон UI с production backend. VoiceOver, macOS 14 и открытие реальных разрешённых файлов не проверялись. Снимки реального окна не приложены из-за ограничений сохранения CUA capture; см. [QA README](../artifacts/sa-04-swiftui-qa/README.md) и [testing](testing.md).
