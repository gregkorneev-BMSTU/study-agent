# Python backend bridge: черновик контракта

← [Разработка](README.md) · [Wiki](../README.md)


**Статус:** базовый контракт SA-01; расширения локальной SA-03 перечислены ниже. Поле `search.result.warnings` добавлено SA-02. Клиенты, не использующие новые команды, продолжают получать прежний envelope.

Backend запускается локально как отдельный процесс, а клиент обменивается с ним сообщениями JSON Lines через stdin/stdout. Документы и обработка остаются на машине пользователя. Транспорт не является сетевым API.

## Транспорт и envelope

- Каждая команда передаётся одной JSON-строкой, завершающейся `\n`. Успешный ответ или ошибка — отдельная JSON-строка. Диагностические сообщения процесса не должны попадать в stdout; stdout зарезервирован протоколу, stderr — логам процесса.
- Клиент генерирует строковый `request_id` и передаёт его в запросе. Backend возвращает то же значение как `request_id` в обычном ответе. Поле пока не обязательно для Python dispatch; при ошибке разбора JSON или неверном корневом типе ответа может не содержать `request_id`.
- Успешный ответ: `{"request_id":"…","ok":true,"result":{…}}`.
- Ошибка команды: `{"request_id":"…","ok":false,"error":{"message":"…"}}`. Текущая реализация возвращает человекочитаемое сообщение и `code`; для занятой блокировки это `index_busy`, для остальных ошибок пока используется общий `backend_error`.
- Во время команды могут приходить промежуточные события: `{"event":"progress","result":{"current":N,"total":N}}`. Новые события содержат `request_id`; клиент должен распознавать их по `event` и совпадающему `request_id`, продолжая читать поток до финального envelope с тем же идентификатором.
- Неизвестные поля и команды сейчас не имеют закреплённой гарантии совместимости. Клиенты должны проверять `ok`, требуемые поля результата и корректно показывать `error.message`.

## Расширения SA-03 в `feature/sa-03-rag`

- `list_embedding_models` возвращает `models:[{name,dimensions}]`, отбирая установленные локальные модели с capability embedding по `/api/show`.
- `embedding:{model,dimensions,document_prefix?,query_prefix?}` — необязательный профиль для `index_source`, `sync_source`, `index_status`, `search`, `answer`. Runtime проверяет digest и remote metadata; автоматической загрузки нет.
- `index_source`/`sync_source` сначала фиксируют текстовую индексацию, затем считают недостающие embeddings. При ошибке второй фазы текст остаётся доступен. Есть progress `phase=embedding` и финальный необязательный `embeddings:{embedded,skipped,stale,cancelled}`.
- `index_status` с профилем дополнительно возвращает `embedding_total`, `embedding_ready`; при недоступном runtime — `embedding_error=true`, не теряя текстовых счётчиков.
- `search` принимает `search_mode:lexical|semantic|hybrid` (default lexical). Возвращает прежние hits/warnings/indexing плюс `search_mode` и `embedding_pending`. score остаётся Int; численные шкалы между режимами несопоставимы.
- **`answer` теперь требует `roots` и получает контекст повторным retrieval из SQLite.** Переданные клиентом `hits` игнорируются; старым клиентам, присылающим только hits, возвращается ошибка валидации. Это намеренное изменение для отказа от доверия UI-контексту; оба локальных клиента обновлены, Windows-ветке нужна адаптация.
- Ответ `answer`: `{answer,sources:[SearchHit],grounded:Bool}`. Sources — только процитированные фрагменты, номера в ответе и sources согласованы. При отсутствии данных/отказе: локализованный answer, пустые sources, grounded=false. При ошибке модели прежняя поисковая выдача сохраняется клиентом.
- Новые коды ошибок: `embedding_required`, `embedding_error`, `model_unavailable`, `invalid_citations`; прочие прежние коды сохраняются. Клиент локализует по code.
- Необязательные поля `SearchHit`: `related_count` (скрытые кандидаты того же раздела), `quality_warnings` (сейчас `formula_suspect`). Они не означают число всех совпадений или математическую проверку истинности.
- `full_excerpt` — необязательный полный текст сохранённого чанка до выбора формулы/ограничения контекста. SwiftUI использует его для Original Text, с fallback на `excerpt` у старого backend. `excerpt` остаётся выдержкой для генерации; полный чанк не расширяет лимит контекста модели. Схема SQLite не меняется.
- Для `invalid_citations` error содержит `reason`, `stage:"answer"`, `model`, локализованные `message`/`action` и `details:{source_count,invalid_sources?,paragraph_index?,warning_codes?}`. Причины: `missing_citations`, `unknown_source`, `uncited_paragraph`, `generated_links`, `source_quality`. Номер абзаца начинается с 1. Текст отклонённого ответа и содержимое источников в эти поля не включаются. Клиент сохраняет поисковые hits и различает успешный поиск и отклонение ответа.

Актуальная реализация и ограничения: [SA-03 поиск](sa-03-search.md). Описания `answer` и прочих команд ниже фиксируют прежний контракт выпущенной Beta 4; изменения ветки SA-03 имеют приоритет.

## Команды выпущенной Beta 4

### `index_source` / `sync_source`

Обе команды запускают одну и ту же первичную или инкрементальную обработку выбранной папки. Отдельной JSONL-команды отмены нет: macOS-клиент отменяет Swift task и завершает выделенный helper-процесс. Запись каждого документа атомарна, поэтому уже сохранённые документы остаются в индексе. При завершении процесса финальный envelope может не прийти; UI должен показать отмену и не отмечать синхронизацию завершённой.

```json
{"request_id":"UUID","command":"sync_source","root":"/path/to/folder","verify_hash":false}
```

`root` — обязательная строка локального пути. `verify_hash` необязателен и включает принудительную проверку SHA-256; обычная синхронизация сравнивает относительный путь, размер и `st_mtime_ns`. Во время работы приходят события `progress` с полями `phase`, `current`, `total`, `indexed`, `partial`, `skipped`, `failed`. Финальный `result` содержит `source_id`, те же счётчики, `removed`, `cancelled` и `errors` (массив `{document_id,code}`). `phase` принимает `scanning`, `indexing`, `complete` или `cancelled`. Ошибки отдельных документов, в том числе `document_disappeared`, `permission_denied` и `document_stat_failed` при чтении метаданных файла, не прерывают обработку остальных. macOS-клиент последовательно ставит источники в очередь, чтобы одновременное добавление папок не теряло запросы при занятой блокировке. При занятой другим процессом блокировке финальный error envelope содержит `code: "index_busy"`; клиент повторяет этот запрос после задержки.

### `index_status`

Запрос: `{"command":"index_status","root":"/path/to/folder"}`. Результат содержит `source_id`, `documents`, `ready`, `partial`, `failed`, `chunks`, `last_indexed_at` (SQLite datetime либо `null`) и `issues` — сохранённые `{document_id,title,code,page_number}` из ошибок и предупреждений SQLite. Это позволяет восстановить проблемы документов после перезапуска без отдельной схемы хранения. Время берётся из `sources.indexed_at` и устанавливается после полного прохода; после отменённого прохода не обновляется. Для статуса доступность самой папки не требуется: данные читаются из SQLite. Клиенты игнорируют неизвестное поле; клиенты macOS, требующие совместимости со старыми backend, декодируют `issues` как необязательное.

### `remove_index_source`

Запрос: `{"command":"remove_index_source","root":"/path/to/folder"}`. Результат: `{"removed":true}`. Удаляются записи индекса этого источника, исходные файлы не изменяются.

### `list_sources`

Запрос:

```json
{"request_id":"UUID","command":"list_sources","roots":["/path/to/folder"]}
```

Результат `result.sources` — массив объектов:

```json
{"name":"folder","path":"/path/to/folder","document_count":12,"available":true}
```

`roots` обязателен и является массивом строковых путей. `available=false` означает временно недоступный корень; `document_count` тогда берётся из сохранённого индекса. `path` — абсолютный путь на машине пользователя: он нужен UI локально и не должен отправляться в телеметрию, облачные сервисы или репозиторий.

### `search`

Запрос:

```json
{"request_id":"UUID","command":"search","roots":["/path/to/folder"],"query":"вопрос или ключевые слова"}
```

Результат `result.hits` — массив, отсортированный по убыванию совпадений, максимум 8 элементов:

```json
{"title":"Название","document_id":"relative/path.txt","excerpt":"…совпавший контекст…","score":3,"source_root":"/path/to/folder"}
```

Поле `result.indexing` равно `true`, если хотя бы один запрошенный источник ещё не завершил первую индексацию (включая источник, ожидающий очереди). При пустом `hits` клиент показывает состояние обработки, а не окончательное отсутствие совпадений. После успешного полного прохода оно становится `false`; отмена оставляет `true`. Поиск читает ранее сохранённые фрагменты SQLite и не вызывает extractors. Перед первым поиском клиент должен выполнить `index_source` после явного подключения папки. Для временно отключённой папки сохранённые результаты остаются доступны. Пустой запрос без значимых токенов даёт пустой список. `source_root` — абсолютный локальный путь; действует то же ограничение приватности, что и для `list_sources.path`.

У каждого hit могут дополнительно присутствовать `page_number`, `heading`, `marker`, `extraction_type`, `chunk_id`. `page_number` берётся из структурированного PDF-блока; у DOCX он `null`. Клиенты, которым эти поля пока не нужны, могут игнорировать их.

В PR #10 результат также содержит `warnings` (массив, возможно пустой). Клиенты, использующие только `hits`, продолжают работать. Предупреждение имеет вид `{"document_id":"relative/broken.docx","title":"broken","code":"document_extraction_failed","page_number":null}`. Возможные коды: `document_extraction_failed`, `ocr_failed`. Для OCR страницы `page_number` содержит номер с единицы. Поле не содержит текста исключения, содержимого документа или абсолютного пути. Клиент локализует сообщение по `code` и показывает предупреждения рядом с доступными совпадениями, включая случай пустого `hits`.

### `answer`

Запрос:

```json
{"request_id":"UUID","command":"answer","model":"qwen3.5:4b","query":"вопрос","language":"ru","hits":[{"source_root":"/path/to/folder","document_id":"relative/path.txt","excerpt":"фрагмент"}]}
```

- `model`, `query` должны быть непустыми строками; `hits` — массив объектов с непустыми строками `source_root`, `document_id` и `excerpt`.
- Backend использует не более первых пяти `hits`, формирует из них контекст и передаёт локальному Ollama. Сейчас результат возвращает только `answer`; клиенты, показывающие источники, хранят и отображают тот же префикс до пяти объектов, отправленный в запросе, и только после непустого успешного ответа. Метаданные источников берутся из поисковых `hits`, а не из текста модели.
- `language` поддерживает `ru` и `en`; отсутствующее или иное значение преобразуется в `None` и не является ошибкой контракта.
- Результат: `{"answer":"текст ответа"}`.
- `title` и `score` в объектах `hits` backend не использует.

### `list_models`

Запрос: `{"request_id":"UUID","command":"list_models"}`.

Результат: `{"models":["qwen3.5:4b"]}` — список моделей, доступных локальному Ollama. Недоступность Ollama возвращается через общий error envelope.

### `diagnose_backend`

Запрос: `{"request_id":"UUID","command":"diagnose_backend"}`.

Результат:

```json
{
  "backend_healthy": true,
  "pdf_available": true,
  "ocr_runtime_available": true,
  "ocr_weights_state": "installed"
}
```

`ocr_weights_state` сейчас принимает `installed` или `missing`. Проверка наличия весов локальная и не загружает модель/не вызывает OCR.

### `install_ocr_model`

Запрос: `{"request_id":"UUID","command":"install_ocr_model"}`.

Во время загрузки могут приходить progress-события с `current` и `total`. Эти числа относятся к текущему progress-источнику загрузчика и не гарантируют монотонный общий процент по всей модели. Финальный результат при успехе: `{"ocr_weights_state":"installed","model_path":"/local/app/data/Models/Chandra"}`. `model_path` — абсолютный локальный путь, не публиковать его.

Загрузка требует optional OCR dependencies и сети, вызывается только по явному действию пользователя. Ошибка загрузки возвращается общим error envelope. В текущем macOS-клиенте запрос поддерживает отмену процесса; Windows-клиенту для эквивалентности понадобятся чтение progress и отмена, если установка OCR будет подключена к UI.

## Фактическое покрытие клиентов

SwiftUI-клиент вызывает прежние шесть команд и новые `index_source`/`remove_index_source`; для длительных операций читает progress-события.

На дату проверки `origin/feature/sa-05-windows` содержит WinUI 3 клиент и Python bridge service для `diagnose_backend`, `list_sources`, `search`, `list_models` и `answer`. В видимой реализации `AnswerAsync` всегда отправляет `language: "ru"`; `install_ocr_model` и progress-события в сервисе не реализованы. Ветка не влита в `main`, Windows-сборка не проверена этой страницей. Перед объявлением общего контракта нужно согласовать локаль ответа и поддержку необязательной OCR-команды/потоковых событий.

## Версионирование и следующие решения

В запросах и ответах пока нет номера версии протокола. Для первой совместимой фиксации можно считать этот документ **Draft 1**, но не заявлять версионирование в runtime до отдельного изменения кода. Изменения полей и команд следует сначала согласовать между SwiftUI и WinUI клиентами, добавить/обновить тесты `tests/test_mac_bridge.py`, затем обновить этот документ. Рекомендуемое решение перед фиксацией: одинаковый набор поддерживаемых команд и язык ответа из пользовательской настройки; установка OCR может оставаться явно необязательной командой, если клиенты не показывают её.
